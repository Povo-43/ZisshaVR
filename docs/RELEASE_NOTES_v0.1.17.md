録画が開始できない問題を調査し、原因の修正とエラー表示の改善を行いました。

## 原因と修正

### 1. エンコーダのSurfaceTextureを「開始前」に取得していた
RootEncoderは`startRecord`/`startStream`の中でレンダラを起動し、その**非同期処理の中で**
エンコーダ用`SurfaceTexture`を生成します。従来は開始**前**に`getSurfaceTexture()`を呼んで
いたため`null`が返り、合成映像がエンコーダへ渡らず(録画が空になる/初期化に失敗する)
状態でした。

- 開始**後**にSurfaceTextureを取得するよう変更(生成されるまで短時間ポーリング)。
- これにより録画MP4に合成映像が入ります。
- GL初期化前にSurfaceTextureが届いた場合も取りこぼさず、初期化後に適用するよう修正。

### 2. エラー内容が分からない(存在しない設定を案内していた)
- 「保存先とコーデック設定を確認してください」という案内は実在しない設定を指しており、
  原因も不明でした。
- **実際の失敗理由**(例外クラスとメッセージ、または「この端末のH.264エンコーダは
  1080x1920に対応していません」等)をSnackbarに表示するよう変更。配信側も同様。

### 3. 端末が解像度を受け付けない場合のフォールバック
- 一部の端末はハードウェアH.264エンコーダで縦向き解像度(1080x1920)を拒否します。
- 次の順に自動で再試行します:
  1. 合成サイズ(例 1080x1920、回転0)
  2. 横縦を入れ替え+回転90
  3. 720x1280
  4. 1280x720 + 回転90

### 4. 保存先の堅牢化
- 外部ストレージが未実装/書き込み不可の場合は**内部ストレージ**へフォールバック
  (MediaMuxerの出力ファイル作成失敗を回避)。
- 録画・配信の解像度を、設定値ではなく**実際の合成サイズ**から取得するよう変更。

## 確認方法
- 録画開始に失敗した場合は、Snackbarに**具体的な理由**が出ます。その文言を送っていただければ
  さらに追い込めます。
- 成功した場合、`Android/data/dev.zissha.vr/files/Movies/recordings/` にMP4が作成され、
  ギャラリーにも登録されます。
